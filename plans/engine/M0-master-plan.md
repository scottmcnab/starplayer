## Why this milestone exists

No tracker code at all. M0 does two things: it stands up the workspace and CI so every
later milestone inherits the invariants for free, and it **de-risks the AudioWorklet
path before anything depends on it**.

The AudioWorklet spike is first because it carries the project's highest uncertainty
*and* sits on the critical path to the owner's chosen first deliverable. The known
hazards: no `SharedArrayBuffer` without COOP/COEP headers; no `fetch` or dynamic
`import` inside a worklet in some browsers, so the wasm module must arrive as bytes via
`postMessage`; a hard 128-frame render quantum; growing wasm memory on the audio thread
causes an audible glitch; `wasm-bindgen` output needs manual massaging for worklet
scope. A sine wave exercises every one of them.

The block-size determinism test lands here too, before there is any format code, so the
bug class it guards against (architecture §1.4) can never be introduced.

## Exit criteria

1. `cargo test --workspace` passes on host.
2. `cargo build --target wasm32-unknown-unknown` succeeds.
3. `cargo check --target riscv32imc-unknown-none-elf -p starplayer-core --no-default-features`
   succeeds, and the same for every other `no_std` crate.
4. `cargo clippy --workspace -- -D warnings` is clean.
5. The block-size determinism test passes at sizes 1, 3, 64, 128, 4096, 8191.
6. **A browser tab plays a sine wave generated by Rust running in an AudioWorklet.**

sine wave and a green CI matrix, nothing more.
