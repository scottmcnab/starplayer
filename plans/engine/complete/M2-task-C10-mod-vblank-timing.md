## Context for a fresh agent

StarPlayer is a `no_std + alloc` Rust tracked-music engine. Read `AGENTS.md` first: the
design invariants there (sample-exact ticks, buffer-size-independent output, no
allocation/locks/panics in `render()`, format identity, quirks as data) are
non-negotiable. Then read `plans/product/03-accuracy-policy.md` §2 *Tracker dialects* and
`crates/starplayer-core/src/quirks.rs` top to bottom — this task adds one field to
`QuirkSet` and one detection layer above the loader, in exactly the shape those two
documents prescribe.

### The bug

The owner's favourite MOD, `K-P-K.MOD` ("Klisje paa klisje", 4-channel `M.K.`, 93
orders, June 1993), plays the second half of the song about four times too slowly. The
file is **not** in the repository (third-party, no licence) and must not be added; it
lives at `/mnt/c/Users/scott/Documents/Projects/music/old/K-P-K.MOD` for the owner's
listening check only. Its relevant cells, decoded from the file:

| Order | Pattern | Row | Channel | Cell |
|---|---|---|---|---|
| 31 | 32 | 63 | 4 | note 428, instrument 11, `F20` — with a four-note chord on the row |
| 32 | 20 | 0 | 1 | `F04` |
| 82 | 59 | 63 | — | `F30` |

No row anywhere in the file carries both an `Fxx` below `0x20` and one of `0x20` or
more. There is one `Bxx`/`Dxx` in the whole song.

ProTracker 2 (`mt_SetSpeed`, `CMP.B #32 / BHS SetTempo`) reads `Fxx` with `xx >= 32` as
a CIA tempo in BPM. Our MOD processor implements that rule at
`crates/starplayer-mod/src/processor.rs` (`0xF if cell.param < 32 => speed`, else a
deferred tempo). So `F20` sets **BPM 32**, the `F04` on the next row only restores the
speed, and BPM 32 sticks for the remaining 61 orders. The two readings of the file:

| Reading | Song length |
|---|---|
| CIA (PT2 rule; StarPlayer today) | 29.1 min |
| VBlank (every `Fxx` is ticks per row) | 10.7 min |

The composer's intent is plain from the cells: `F20` and `F30` each sit on the **last row
of a section, under a chord**, and the next pattern immediately sets `F04` again. They
are fermatas — a 32-tick and a 48-tick hold — written on a tracker that had no CIA tempo
at all, where `Fxx` is always ticks per row. That is a **VBlank-timed MOD**: the tracker
interrupt ran off the 50 Hz vertical blank, not the CIA timer, so there is no BPM to set.
ProTracker itself has a VBlank mode; NoiseTracker and SoundTracker only have it.

### Why the original DOS player gets the first one right (and the second one wrong)

`STARPLAY-2.25s/S3MLIB.ASM` `ConvertValues` (line 1772; identical at
`STARPLAY/S3MLIB.ASM:1815`) uses an **inclusive** boundary:

```asm
		cmp al,32
		jbe @speed
		mov [_SFxNum],20                ;set bpm
```

so it reads `F20` as speed 32 — the right result for this row, by an off-by-one against
ProTracker 2. `F30` (48) is above 32 even for the original, so `STARPLAY.EXE` should drop
to BPM 48 from order 83. That inclusive boundary is a defect under the accuracy policy's
rule (ProTracker would not have done it) and is **not** to be copied; it becomes a §3
deviation entry instead (deliverable 6). The VBlank reading fixes both rows.

### How the two reference players detect this

Both libxmp and OpenMPT already solve this class of file, and the corpus this repo's
conformance harness is pinned to was generated by libxmp, so **libxmp's rules are the
specification** and OpenMPT's are the cross-check.

**libxmp**, commit `6ec0ba21b1b28f91e22b68a51d59207c6bbf6139` (the commit
`plans/reference/format-notes-mod.md` pins; clone it if no checkout is around — the
working copies at `/tmp/starplayer-libxmp-c*/` may or may not still exist):

- `src/loaders/mod_load.c:76-95` — the tag table. `M&K!` and `N.T.` are
  `TRACKER_NOISETRACKER`; `M.K.` / `M!K!` are ProTracker; `LARD` and `NSMS` are
  *unknown*, not NoiseTracker.
- `src/loaders/mod_load.c:99-108` — `tracker_is_vblank()`: NoiseTracker and SoundTracker
  ids are VBlank-only.
- `src/loaders/mod_load.c:815-838` — per-pattern evidence while reading cells: any
  `Fxx >= 0x20` sets `compare_vblank = 1`, `high_fxx = 1` and records the value in
  `pat_high_fxx[pattern]`; a row with both a low and a high `Fxx` sets `samerow_fxx`.
- `src/loaders/mod_load.c:890-950` — the decision: a VBlank-only tracker id gets
  `QUIRK_NOBPM` outright with no comparison; `samerow_fxx` cancels the comparison (and
  demotes a NoiseTracker id to unknown); otherwise, if `high_fxx` and `len >= 8` and the
  *only* patterns with a high `Fxx` are in the last two orders, and the last such value is
  not `0x7D` (125, the CIA default, which means "this was converted to play as CIA"), the
  module is VBlank with no comparison ("silence added at the end of the song").
- `src/scan.c:50` — `VBLANK_TIME_THRESHOLD 480000.0` ms (8 minutes) — and
  `src/scan.c:671-708` `compare_vblank_scan()`: when `compare_vblank` is set and the
  first scan's one-pass time is at or above the threshold, rescan with `QUIRK_NOBPM`
  toggled and **keep the shorter**; on a tie keep the original.
- `src/effects.c:463-472` — under `QUIRK_NOBPM` (or the host's `XMP_FLAGS_VBLANK`) every
  non-zero `Fxx` is a speed change, whatever its value.

**OpenMPT** `soundlib/Load_mod.cpp` (current master, for cross-checking only): only
`M.K.` / `M!K!` files are considered; a tempo command below 100 BPM sets
`hasTempoCommands`; a row with both a speed and a tempo command, or any sample longer
than the tracker could have had, sets `definitelyCIA`; if the CIA song length is at least
480 s the loader switches to `kMODVBlankTiming`, then reverts if the VBlank length is not
shorter.

For `K-P-K.MOD` both heuristics fire (high `Fxx` present, no mixed row, CIA length far
past 8 minutes, VBlank length shorter) and neither counter-signal is present.

### Where this fits the existing design

- `FormatDialect` is what the **file header** says; its doc comment promises it is set once
  from the header alone and never revised. Do not put a pattern-derived decision in it.
  `FormatDialect::ProTracker3` exists precisely because "libxmp's own timing heuristics
  key off it" — this is that use.
- `QuirkSet` is the flat, `Copy`, resolved-once answer. The new behaviour is one field of
  it. Nothing exposes a setter; a host that wants a different timing loads the module
  again or passes `QuirkSelection::Override`.
- The length comparison needs a sequencer, so it cannot live in the loader
  (`load()` must stay cheap: fuzz targets call it, and a scan has a million-tick budget).
  It lives in the **facade**, next to the scan both hosts already do:
  `crates/starplayer-offline/src/lib.rs` `song_timeline_with_limits` and
  `crates/starplayer-host-wasm/src/lib.rs` `scan_for` each build a throwaway sequencer
  with `QuirkSelection::FromDialect`, call `scan_timeline`, then build the playback
  sequencer with `FromDialect` again. After this task the scan **produces** the quirks the
  playback sequencer is built with, so the two can never disagree.

## Deliverables

1. **`ModTiming` and `QuirkSet::mod_timing`** in `crates/starplayer-core/src/quirks.rs`:

   ```rust
   /// Which interrupt a MOD's tracker tick ran off (accuracy policy §2, *Tracker dialects*).
   #[derive(Copy, Clone, Debug, Default, PartialEq, Eq, Hash)]
   pub enum ModTiming {
       /// The CIA timer: `Fxx` below 32 sets ticks per row, 32 and above sets BPM. ProTracker 2's rule and the default.
       #[default]
       Cia,
       /// The vertical blank: there is no BPM, so every non-zero `Fxx` sets ticks per row. NoiseTracker, SoundTracker and ProTracker's own VBlank mode.
       VBlank,
   }
   ```

   `canonical()` and every named constructor keep `Cia`. Extend
   `canonical_and_classic_differ_only_where_the_policy_says_so` with the new field — the
   classic profile is also `Cia`. Doc comments follow the file's existing style: name the
   policy entry, say what the oracle sees.

2. **The processor honours it.** In `crates/starplayer-mod/src/processor.rs` the `0xF`
   arm treats every non-zero parameter as a speed change when
   `self.quirks.mod_timing == ModTiming::VBlank`; `F00` keeps its existing
   `mod_f00_stops_song` behaviour; the deferred CIA latch (`pending_tempo`) is never
   armed under VBlank. `EffectSemantics::MultiTracker` is unaffected (MTM is always CIA;
   the field is read only on the ProTracker path). Unit tests: under `VBlank`, `F20`
   gives speed 32 and `F30` speed 48 with `tempo_bpm` untouched and no pending tempo;
   under `Cia` the existing `speed_and_tempo_split_at_thirty_two_and_f00_stops` still
   passes unchanged.

3. **Loader evidence.** `starplayer-mod` records, while it reads the patterns, the cheap
   facts libxmp records, and exposes them as one `Copy` struct — call it
   `ModTimingEvidence` — reachable from a loaded `Module` (store it in the header's
   `format_extra` bits, which exist for format-owned facts, or as a small side table the
   crate owns; do not add a format-neutral `ModuleHeader` field for it):

   - `has_high_fxx`: some cell has `Fxx` with `xx >= 0x20`.
   - `mixed_row`: some row has both an `Fxx < 0x20` and an `Fxx >= 0x20` across its
     channels.
   - `high_fxx_only_at_end`: libxmp's end-silence rule — `len >= 8`, no high `Fxx` in
     any pattern referenced by orders `0..len-2`, and the last order (searching backwards
     over the final two) whose pattern has a high `Fxx` does not have `0x7D` as that
     pattern's *last* high value. Reproduce libxmp's exact loop from the pinned source
     (`mod_load.c:919-946`), not this paraphrase.
   - `vblank_only_tag`: the tag maps to a tracker libxmp calls VBlank-only — `M&K!` and
     `N.T.`, per `mod_magic[]`. Note our loader currently maps those two **and** `LARD` /
     `NSMS` to `FormatDialect::ProTracker3`; only the first two are NoiseTracker in libxmp.
     Either split the dialect (`Noisetracker` vs `ProTracker3`) or key this bit off the
     tag directly — research point 1 decides.

   A pure function on the evidence gives the verdict, mirroring
   `mod_load.c:890-950` in order:

   ```rust
   pub enum TimingVerdict { Cia, VBlank, CompareLengths }
   ```

   `vblank_only_tag && !mixed_row` → `VBlank`; `mixed_row` → `Cia`;
   `high_fxx_only_at_end` → `VBlank`; `has_high_fxx` → `CompareLengths`; otherwise `Cia`.
   Unit tests per branch on hand-built modules (the crate's tests already build minimal
   `M.K.` byte images — reuse that helper).

4. **The resolver, in the facade.** A single function in `crates/starplayer/src/lib.rs`
   (or a small module it re-exports) that both hosts call instead of their private
   format matches:

   ```rust
   pub struct ScannedSong { pub timeline: SongTimeline, pub quirks: QuirkSet }
   pub fn scan_song(module: &Arc<Module>, sample_rate_hz: u32, limits: ScanLimits) -> Result<ScannedSong, Error>;
   ```

   For S3M and MTM it resolves `QuirkSelection::FromDialect` and scans once. For MOD it
   resolves the dialect's quirks, takes the verdict from deliverable 3, and:

   - `Cia` → one scan;
   - `VBlank` → one scan with `mod_timing = VBlank`;
   - `CompareLengths` → scan with `Cia`; if the one-pass length is at least
     **480 seconds**, or the scan ended on `EndReason::Budget`, scan again with `VBlank`
     and keep whichever timeline is **shorter**, ties to `Cia`.

   Keep the threshold as a named constant with libxmp's file and line in its doc comment.
   The second scan is the only new cost and only ever runs on a MOD that already takes
   eight minutes to scan through once, so no host needs a new code path for it.

   Then **both hosts** build their playback sequencer with
   `QuirkSelection::Override(scanned.quirks)`:

   - `crates/starplayer-offline/src/lib.rs`: `song_timeline` / `song_timeline_with_limits`
     become thin wrappers over `scan_song` (keep their signatures — tests use them — or
     return the `ScannedSong` and fix the callers), and every render path that today
     builds a sequencer with `FromDialect` after scanning (`render_to_end` and friends
     around line 374, the golden driver around lines 873 and 1003) uses the scan's
     quirks. If a path renders without scanning, it must scan first; there is no
     "render with unknown timing".
   - `crates/starplayer-host-wasm/src/lib.rs`: `scan_for` returns the `ScannedSong`;
     `source_for` takes the cached scan (not just the cached timeline — the mixer-mode
     rebuild path caches it, and it must carry the quirks too) and builds the sequencer
     from `scanned.quirks`. The comment "the web player exposes no override yet" stays
     true: the override comes from the scan, not from the UI.
   - `apps/starplayer-cli` if it builds sequencers directly: same rule.

## Research points

1. **`M&K!` / `N.T.` versus `LARD` / `NSMS`.** libxmp treats the first pair as

   into `FormatDialect::ProTracker3`. Decide whether to add a `Noisetracker` dialect
   (which then maps to `mod_timing: VBlank` in `FormatDialect::quirks()`, the cleanest
   answer, and what the `ProTracker3` doc comment anticipated) or to keep one dialect and
   derive `vblank_only_tag` from the tag. Prefer the new dialect unless it breaks a
   pinned corpus case; record which cases (if any) carry those tags and what happened.
2. **The corpus.** Search the pinned libxmp corpus and the harness's exclusion/waiver
   list (`plans/reference/format-notes-mod.md` and the conformance crate) for MOD cases
   with an `Fxx >= 0x20`. For each, say whether libxmp's dump was generated under VBlank,
   whether our new verdict agrees, and whether any previously waived or excluded case now
   passes (if so, un-waive it in the same change). Do not regenerate goldens; if a golden
   fixture changes timing under the new resolver, stop and report it in the final
   summary — that is a finding for the owner, not something to paper over.
3. **`EndReason::Budget` on the first scan.** A CIA scan that runs out its one-hour
   budget is by definition past the threshold. Confirm the VBlank rescan gets a fresh
   budget and that a module which is over budget both ways keeps `Cia`.
4. **OpenMPT's long-sample and `< 100 BPM` gates.** Decide whether either is worth adding
   on top of libxmp's rules. The default answer is no — the oracle is libxmp — but if a
   synthetic test shows libxmp's rules alone misclassify an obviously-CIA module, say so.

## Research resolution

Recorded at implementation time; each answer is the decision, not a summary of the
question.

### 0. One correction to the spec's paraphrase — the timing-detection gate

The spec collapses libxmp's decision into five ordered tests
(`vblank_only_tag && !mixed_row` → VBlank; `mixed_row` → Cia; `high_fxx_only_at_end` →
VBlank; `has_high_fxx` → CompareLengths; else Cia). Read from the pinned source that
ordering is wrong for every tag that is not `M.K.` or `M!K!`.

`mod_load.c:897` is `if (!needs_timing_detection) { … m->compare_vblank = 0; } else if
(samerow_fxx) … else if (high_fxx && mod->len >= 8) …`, and `needs_timing_detection` is
set at `:530-531` **only** for `TRACKER_PROTRACKER`, which `mod_magic[]` gives to `M.K.`
and `M!K!` alone. So a Startrekker, Octalyser, Digital Tracker, FastTracker, TakeTracker,
`LARD` or `NSMS` file never reaches the pattern evidence at all: it is CIA, with no
comparison, however many high `Fxx` bytes it contains. The spec's ordering would have made
all of those `CompareLengths`.

The evidence struct therefore carries a fifth field, `timing_detection`, and
`timing_verdict` opens with it. That also matters for the corpus: `pattern_loop_dt.mod`
(`FA06`) and the three Octalyser fixtures all carry high `Fxx` values, and under the
spec's ordering they would have entered the comparison path.

### 1. `M&K!` / `N.T.` versus `LARD` / `NSMS` — **a new `Noisetracker` dialect**

`FormatDialect::Noisetracker` added, taking `M&K!` and `N.T.`; `LARD` and `NSMS` stay
`FormatDialect::ProTracker3`, which is what libxmp's `mod_magic[]` says (they are
`TRACKER_UNKNOWN` there, not NoiseTracker). `FormatDialect::Noisetracker.quirks()` is
`QuirkSet::noisetracker()` — `mod_timing: VBlank` and nothing else changed from
`protracker()`. This is the cleanest of the two offered answers and the one the
`ProTracker3` doc comment anticipated; the `vblank_only_tag` evidence bit is derived from
the same tag match, so the loader, the dialect and the verdict cannot disagree.

**No pinned corpus case carries any of the four tags.** Every MOD case in `cases.tsv`
decodes as `M.K.` (17 cases), `FLT4` (5), `CD61` (3), `FA04` (1) or `FA06` (1). Nothing
was un-waived and nothing moved: the corpus stands at **33 of 47** (MOD 16/27, S3M 16/17,
MTM 1/3), exactly the numbers in `plans/README.md`.

One libxmp behaviour is deliberately **not** reproduced: `get_tracker_id`
(`mod_load.c:305-470`) can reclassify a file to `TRACKER_NOISETRACKER` or
`TRACKER_SOUNDTRACKER` from the restart byte, loop sizes, `ST-` instrument names and
empty-instrument volumes, and for a non-`M.K.` tag that reclassification would reach
`tracker_is_vblank`. Reproducing it means importing libxmp's whole tracker-identification
heuristic, which is a `FormatDialect` change well past this task's "out of scope" line, and
it is unobservable on the pinned corpus — every case there is already timed the way
StarPlayer times it, which the unchanged 33 of 47 confirms. If a real file ever needs it,
it is a `FormatDialect` task of its own.

### 2. The corpus — **two cases contain a high `Fxx`; neither is VBlank and neither moved**

### 3. `EndReason::Budget` on the first scan — **rescan, with a fresh budget, and CIA wins a tie of two truncated lengths**

Confirmed and tested (`a_cia_scan_that_runs_out_of_budget_is_rescanned_and_a_hopeless_one_keeps_cia`).
A CIA scan that ends on `EndReason::Budget` never reached the end of one pass, so it is
past the threshold by definition; the resolver treats `Budget` as "over the threshold" and
rescans without comparing `end_frame` against 480 seconds at all. The second scan is
`scan_timeline` on a second, freshly built sequencer with the *same* `ScanLimits` value —
`ScanLimits` is `Copy` and the tick and frame counters are local to each call, so the
rescan gets a full budget rather than the first scan's remainder.

Where both scans end on `Budget`, the two `end_frame` values are both artefacts of the
leash rather than song lengths, and comparing them would pick a timing on noise. The
resolver keeps CIA in that case explicitly.

### 4. OpenMPT's long-sample and `< 100 BPM` gates — **the long-sample gate yes (because libxmp has it), the BPM gate no**

The long-sample gate is not an OpenMPT-only idea: libxmp applies the same test at
`mod_load.c:637-642` — `mh.ins[i].size >= 0x8000` sets `TRACKER_OPENMPT` and clears
`needs_timing_detection` — so it is part of the oracle's own decision and is implemented
here as `ModTimingEvidence::timing_detection`. It fires on a real corpus module
(`VibratoReset.mod`), which is why it is not theoretical. libxmp's other two
detection-disabling cases, Mod's Grave (`.WOW`) and FlexTrax, need loader features
StarPlayer does not have — it neither detects nor accepts either format — so they cannot
arise.

OpenMPT's `< 100 BPM` gate and its `definitelyCIA` sample-length rule are **not** added.
The oracle is libxmp, the two heuristics disagree on which side of the line a `F64`–`F7C`
byte falls, and adding OpenMPT's would mean this repository's verdicts no longer match the
implementation that generated the pinned dumps. No synthetic module was found where
libxmp's rules alone misclassify an obviously-CIA file: the two counter-signals that
matter in practice — a mixed row and a trailing `F7D` — are libxmp's own, and the length
comparison's 480-second floor is what stops a deliberately slow short song being sped up
(`a_genuinely_slow_short_module_stays_cia` pins that).

## Post-landing notes (2026-09-03)

Two residuals from the review, both dormant on the pinned corpus and left as recorded
follow-ups rather than widened scope:

- **The conformance trace path resolves timing from the dialect alone.** `trace_loaded` in
  `crates/starplayer-offline/src/lib.rs` (behind the `trace` feature) builds its MOD
  processor with `ModProcessor::new`, which resolves `QuirkSelection::FromDialect`. A
  `M&K!` file therefore traces under VBlank, but the pattern-evidence and
  length-comparison verdicts never reach a trace. No pinned case resolves to VBlank, so
  conformance output is unchanged. If a future corpus case does, the fix is to compute
  `starplayer::scan_song(...)?.quirks` in `trace_loaded` and build the `Mod` arm with
  `ModProcessor::with_semantics_and_quirks(..., QuirkSelection::Override(quirks))`.
- **Mod's Grave `.WOW` and FlexTrax files** carry `M.K.` magic, so the loader accepts them
  as plain MODs and runs timing detection on them where libxmp disables it. Both are
  already misparsed for unrelated reasons (channel count, trailing data); a `.WOW`
  loader, if one is ever wanted, should set the evidence's `timing_detection` false.
